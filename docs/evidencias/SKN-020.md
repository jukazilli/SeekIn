## Resultado

A Edge Function `health` entrega liveness público e readiness protegido, valida a resposta com Zod,
preserva correlação, usa códigos estáveis e não consulta dados de aluno.

## Critérios de aceite

| Critério | Resultado | Evidência |
|---|---|---|
| liveness Cloud válida | Passou | HTTP 200, `HEALTH_OK` |
| readiness Cloud válida | Passou | HTTP 200, `HEALTH_OK` com JWT sintético efêmero |
| readiness sem permissão | Passou | HTTP 401, `AUTH_REQUIRED` |
| correlação preservada | Passou | headers e body retornaram o ID enviado |
| contrato compartilhado alinhado | Passou | `AUTH_REQUIRED` aceito por `healthResponseSchema` |
| resposta sem detalhe interno | Passou | somente código, correlação, serviço, status e versão |

## Segurança e privacidade

O JWT sintético existiu apenas na memória do processo, expirou em cinco minutos e não representou um
usuário real. A função não usa `service_role`, não registra token e retorna `cache-control: no-store`.

## Riscos residuais

Nenhum bloqueador conhecido.
