## Resultado

O Worker Beta foi revertido de forma real da versão corrente para a última versão funcional anterior
e depois restaurado para a versão corrente. Cada transição colocou uma única versão em 100% do
tráfego. Playwright confirmou o SHA esperado no `/health` e a disponibilidade do shell nas duas
versões.

No Supabase Dev isolado, uma migration sintética criou uma tabela e uma linha dentro de transação e
falhou deliberadamente ao adicionar uma constraint incompatível. A transação foi abortada, o objeto
parcial desapareceu e os fingerprints do schema e dos dados permaneceram idênticos. O Supabase Beta
recebeu somente uma consulta de integridade.

## Falhas observadas e recuperação

- A primeira consulta longa via `db query` chegou vazia ao endpoint por conter quebras de linha no
  argumento. O SQL foi compactado em um único argumento; a tentativa falha não executou escrita.
- `supabase test db --linked` tentou acessar Docker depois de conectar ao remoto. Como o projeto não
  usa Docker, os mesmos dois arquivos pgTAP foram executados via `supabase db query` e Management
  API cloud.
- A primeira restauração com `versions deploy --env beta` seguiu o redirecionamento gerado pelo build
  e procurou o Worker inexistente `seekin-web`. A API retornou `10007` sem criar deployment. A
  repetição com `--name seekin-web-beta` restaurou o alvo correto.
- O navegador solicitou `/favicon.ico` ao abrir o JSON de health e recebeu 404. O shell final foi
  reaberto em sessão limpa e apresentou zero erro ou warning de console.

## Riscos residuais

- O plano Supabase Free continua sem recuperação física adequada a produção.
- Rollback de Worker não restaura recursos vinculados; compatibilidade de schema continua obrigatória.
- O ensaio prova falha transacional de DDL compatível, não todos os tipos possíveis de migration.
- Restauração física e resposta a perda real de dados permanecem para o `SKN-133`.

## Rollback

O próprio corte terminou restaurado na versão Cloudflare
`e2bc78cb-c2c9-4c7f-8bf3-78cae939421d`, que recebe 100% do tráfego. Em novo incidente, aplicar o
[runbook](../16-runbook-rollback-aplicacao-migrations.md) a uma versão conhecida e compatível. Não
reverter o banco de forma destrutiva.
