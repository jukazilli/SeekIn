# EV-SKN-013 — Supabase Cloud sem Docker

**Item:** SKN-013  
**Estado:** Em desenvolvimento  
**Verificado em:** 2026-09-12T22:47:34Z  
**Commit:** [`8a434bd`](https://github.com/jukazilli/SeekIn/commit/8a434bd)  
**Ambiente:** Supabase Cloud / GitHub Integration

## Resultado

O fluxo foi convertido para Supabase Cloud: não existem scripts de `start`, `stop` ou reset local.
O projeto remoto foi criado e vinculado ao repositório; migrations serão aplicadas a partir de
`main` pela integração oficial. A prova anterior em runner Docker permanece apenas como histórico.

## Critérios de aceite

| Critério | Resultado | Evidência |
|---|---|---|
| projeto cloud explicitamente vinculado | Passou | projeto SeekIn e repositório `jukazilli/SeekIn` |
| fluxo sem Docker | Passou | scripts remotos `push:dry`, `push` e `test` |
| migration aplicada no cloud | Passou | check `Supabase Preview` do commit `8a434bd` |
| pgTAP no cloud isolado | Pendente | requer ambiente de desenvolvimento sem dados reais |
| SKN-010 concluído | Pendente | ver EV-SKN-010 |

## Verificações executadas

O [CI #1](https://github.com/jukazilli/SeekIn/actions/runs/34719324458) comprova que a migration e
o pgTAP eram reproduzíveis antes da decisão cloud-only. A validação atual usa `db push --dry-run`,
GitHub Integration e testes remotos em ambiente isolado.

## Segurança e privacidade

Data API exige grants explícitos (`auto_expose_new_tables = false`).

## Riscos residuais

O plano Free não oferece preview branches automáticas. O banco do beta não pode ser resetado nem
usado para testes destrutivos; falta provisionar o ambiente cloud descartável de desenvolvimento
para executar pgTAP remoto.

## Rollback

Desabilitar a integração GitHub e reverter os scripts. Uma migration já aplicada exige rollback
compatível e nunca reset do projeto do beta.
