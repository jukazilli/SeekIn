# EV-SKN-013 — Supabase Cloud sem Docker

**Item:** SKN-013
**Estado:** Verificado

## Resultado

O projeto `SeekIn G1 Dev`, na organização SeekIn e região `sa-east-1`, funciona como banco Cloud
isolado para desenvolvimento. O fluxo executou dry-run, aplicou três migrations e rodou pgTAP sem
Docker e sem alterar dados do beta.

## Critérios de aceite

| Critério | Resultado | Evidência |
|---|---|---|
| projeto Cloud explicitamente identificado | Passou | ref `ildvwjylcyhbpopjjasi`, projeto `SeekIn G1 Dev` |
| fluxo sem Docker | Passou | `db push --db-url` e Management API oficial |
| dry-run remoto | Passou | listou somente a migration pendente antes de cada aplicação |
| migrations no Cloud isolado | Passou | versões `20260912205531`, `20260913013000` e `20260913020000` |
| pgTAP remoto | Passou | 48/48 asserções |
| beta não resetado | Passou | todos os testes destrutivos ficaram no projeto isolado |

## Verificações executadas

O Supabase CLI `2.117.0` conectou ao Postgres Cloud pelo Supavisor em modo sessão. A camada de
Management API do CLI apresentou erro de transporte neste Windows, por isso queries pgTAP e
advisors foram executados pela Management API oficial com o mesmo PAT, sem exposição de segredo.

## Segurança e privacidade

As credenciais ficam no Gerenciador de Credenciais do Windows. Nenhuma senha, PAT, JWT ou string de
conexão foi gravada no repositório ou nos registros de evidência.

## Riscos residuais

`supabase test db` exige Docker na versão atual do CLI. A suíte é executada diretamente no Postgres
Cloud pela API oficial até o CLI oferecer execução pgTAP remota sem runtime local.

## Rollback

O projeto isolado pode ser pausado ou removido após o ciclo de desenvolvimento. Migrations aplicadas
ao beta só podem ser revertidas por migration corretiva.
